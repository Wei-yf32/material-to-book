# 需求对照表（requirements traceability）

这张表把本项目里用户**逐条提过**的要求，映射到 skill 的具体文件与验收动作。
写书、改版、审校、交付前，逐行对照；任何一行做不到，就是不合格。

编号规则：`A/B/C…` 是主题，末位数字是条目。第三列「验收」是**可执行的检查**，不是形容词。

---

## A. 交付形态

| # | 要求 | 落地位置 | 验收 |
|---|---|---|---|
| A1 | 把文件夹里的资料合并成**一份**汇总讲义 | SKILL.md「先想清楚交付什么类型」；`scripts/build.py merge` | 产出单个合订 PDF，书签一级为卷名 |
| A2 | 支持生成**不同类型**的文档（PDF / HTML / DOCX / PPT / Markdown） | SKILL.md 第 2 节五种类型对照 + 各自路径 | 能说出本任务用哪种、为什么 |
| A3 | 支持**读取代码与文档资料**（PDF、PPTX、DOCX、notebook、源码、CSV） | SKILL.md「支持的输入，怎么读」；`extract_sources.py`、`csvpeek.py`、`pgs.py` | 每类输入都能抽出文本/结构，抽不出的（扫描页）转图读 |
| A4 | 分卷 + 合订都要有 | `book.json` 的 `volumes` / `output`；`build.py` | `_build/pdf/*.pdf` 每卷一份 + 合订一份 |

## B. 内容深度与真实性

| # | 要求 | 落地位置 | 验收 |
|---|---|---|---|
| B1 | 不是搬运，只取关键图/逻辑/数字，**重建**成自己的叙述 | SKILL.md 规范 1；style-guide「深度四层」 | 随机抽 3 段，能在原文找到出处但句子不重样 |
| B2 | 每章要**深化**：直觉 → 形式化 → 真实数字 → 边界 | style-guide「深度四层」 | 四层缺一层即返工 |
| B3 | 加**前沿知识**（论文/新方法），用自己的话重述并配图，附 arXiv/DOI | SKILL.md 规范 13 | 每章 ≥1 处前沿，链接可点开，数字标来源 |
| B4 | 讲得**易懂但不肤浅**（不能只给结论，也不能科普化到失真） | style-guide「读者画像」「深度四层」 | 每个公式后面必须有一句"它在说什么" |
| B5 | 所有数字**可追**：跑出来的贴输出，引用的给出处 | SKILL.md 规范 3；`runpy.py` / `runcc.py` | `checkbook` 无缺失输出；正文数字与输出逐位对得上 |
| B6 | 图必须用**真实/真随机数据**画，不能"画个差不多的糊弄" | SKILL.md 规范 7；`figstyle.py` | 每张图有生成脚本；脚本里有数据来源 |
| B7 | 允许重画原资料里不清晰的图，但必须准确 | style-guide「图」 | 图注写明"与原件一致/差异在哪" |
| B8 | **不要参考**文件夹里已有的 AI 汇总/讲解（质量差），最多当反例 | style-guide「改版时的铁律」 | 交付说明里声明"未复用旧 AI 文稿" |
| B9 | 面向**工科学习 + 工程落地**（不绑定专业）：复杂度 / 内存 / 数据规模 / 部署延迟 / 失败代价都要讲 | SKILL.md 规范 16 | 至少 1 章有「从数据到指标到上线约束」的完整工程案例 |

## C. 原资料（课件/讲义）的处理

| # | 要求 | 落地位置 | 验收 |
|---|---|---|---|
| C1 | 每章要做成原资料的**超集**：原资料讲到的都要讲到 | SKILL.md 规范 8；`cwaudit.py` | 覆盖表逐页，缺页为 0 |
| C2 | 覆盖表逐页映射，处理方式只能写 复述/改写/重绘/新增/合并/无内容 | 同上 | 出现"不采纳"即返工 |
| C3 | 原资料的**导入**（开场动机）要落地，不能直接进定义 | style-guide 章骨架「导入」 | 每章第 1 节是导入，且引用了原资料的开场素材 |
| C4 | 原资料的**例子**要完整落地：表格逐行抄、数字不改、每步算一遍 | SKILL.md 规范 15 | 例子小节有中间值，能和原资料对上 |
| C5 | 原资料的**回顾/小结**要落地成章末回顾块 | SKILL.md 规范 15 | 每章末尾有「原资料回顾」box |
| C6 | 只看文字不够，**示例图要读懂**（图型/轴/刻度/图例/拐点/高亮） | SKILL.md 规范 14；`pgs.py` | 正文对每张关键图有 3~6 句"读图"描述 |
| C7 | 用户要求时，**把原页直接贴进来**（图片或文字），别让读者回去翻 PPT | SKILL.md 规范 7 例外条；`cwembed.py` | 影印页有图注（文件名+总页数），每章 ≤16 张 |
| C8 | 正文**不许写**"课件第 N 页讲了……"这种指路句 | SKILL.md 规范 9；`_scanptr.py` 思路 | 正文 `课件 p` 计数 = 0（图注/覆盖表除外） |

## D. 实验

| # | 要求 | 落地位置 | 验收 |
|---|---|---|---|
| D1 | 每个实验八节：目的/要求/文件结构/阅读顺序/数据/逐段讲码/运行输出/动手改 | `experiment-spec.md`「八节骨架」 | 少一节即返工 |
| D2 | 文件结构用**树状图**，写清每个文件作用，只列本实验用到的 | `experiment-spec.md`「文件树格式」；`INCLUDE-TREE` | 树里不出现 `_build/` 中间产物 |
| D3 | 给**阅读顺序**（按便于理解的顺序，不是按文件名） | 同上第 4 节 | 5 条左右，最后一条是运行命令 |
| D4 | **数据**要给样子：矩阵/表格/字段表；CSV 太大只给一部分 | `experiment-spec.md`「数据节」；`csvpeek.py` | 有形状、每列类型/缺失、前几行、五数概括 |
| D5 | 再配 **1~2 张描述数据的图**（分布/相关性/样本可视化） | 同上；`figstyle.py` | 图注写数据来源 |
| D6 | 代码**整份贴出**，不要用表格说"xx.py 是 xx" | SKILL.md 规范 6 | 每个脚本都有代码块，块顶部是文件条 |
| D7 | 除复现原实验外，要**自己加小实验**（完整代码 + 真实结果） | SKILL.md 规范 15 | 每章 ≥1 个新增实验，且能跑 |
| D8 | 实验的数字要能回答"这说明什么"，不是罗列 | style-guide「深度四层」第 4 层 | 每个实验结尾有"结果怎么读" |

## E. 代码与注释

| # | 要求 | 落地位置 | 验收 |
|---|---|---|---|
| E1 | 每个函数写清 **作用 / 参数（是什么、取什么值）/ 返回（是什么）** | `experiment-spec.md`「docstring 四段」；`docstringify.py` | 每个 `def`/`class` 都有 docstring |
| E2 | 不只是列参数中英文名，要说"这个参数是什么、为什么需要它" | 同上 | 抽查 5 个参数，都有语义解释 |
| E3 | 注释要像 PyCharm 悬停提示那样**多行**，不是一行 `# x = 1` | 同上 | 复杂函数有 4~8 行 docstring |
| E4 | **不要用 print 当小标题**来解释代码 | SKILL.md 规范 6；`_cleanprint` 思路 | 脚本里没有 `print("== 第 1 步 ==")` 式标题 |
| E5 | 函数内部要有**段落注释**，说明这一块在做什么 | `experiment-spec.md` 第 4 节 | 每 5~15 行一条块注释 |
| E6 | 代码块前标出**来源文件**（像 IDE 的标签） | `build.py` 的 `.codefile` 条 | 每个代码块顶部有 `src/volN/xxx.py` |
| E7 | 要**深度总结代码关系**：文件内函数/类怎么配合，调用顺序是什么 | `experiment-spec.md` 阅读顺序 + 代码节导语 | 有 1 段"这三个函数是一条流水线"式说明 |

## F. 语言与编排

| # | 要求 | 落地位置 | 验收 |
|---|---|---|---|
| F1 | 逻辑清晰：每节先说要回答什么，结尾给结论 | style-guide「章骨架」 | 抽查 5 节，符合 |
| F2 | **去 AI 味**：不用"首先/其次/综上所述/值得注意的是/让我们" | style-guide「语言」 | 全文检索禁用词 = 0 |
| F3 | 术语首次出现给英文；符号首次出现给含义与形状 | style-guide「读者画像」 | 抽查 10 个术语 |

| F5 | 图/表/实验/式**编号 = 章号**，不串号 | `numcheck.py` | 全卷 0 处错号 |
| F6 | 单章 15k~35k 汉字（低于 8k 视为搬运） | style-guide「章骨架」 | `checkbook` 汉字数 |

## G. 工程与流程

| # | 要求 | 落地位置 | 验收 |
|---|---|---|---|
| G1 | 可以（也应该）用**多个子代理并行**写不同章 | SKILL.md 阶段 4；`prompts.md` | 每章一个 agent，互不越界 |
| G2 | 子代理**只改自己的章节与自己的 src/figs/out** | `prompts.md` 硬约束段 | 交付时并列 diff 无越界 |
| G3 | 规范先行：先写规范 + 一个样板章，再批量写 | SKILL.md 阶段 3 | 有 STYLE_GUIDE + 样板章 |
| G4 | 改版**只增不减**，确需删要写进交付说明 | style-guide「改版时的铁律」 | diff 里没有无故删除 |
| G5 | 构建要能重复：两遍法回填目录页码、页眉页脚、书签 | `pipeline.md`；`build.py` | 重跑页数稳定，书签页码正确 |
| G6 | 质检脚本化，不靠肉眼 | `qa-checklist.md`；preview/checkbook/numcheck/fix_lt/verify_book | 六道脚本门全绿 |
| G7 | 并发写文件会让构建取到不一致快照 | `lessons.md`（快照一致性） | `build_vol` 只 collect 一次 |

---

## 一句话总结

用户要的不是"把资料排版得好看"，而是：**用真实数字、可复现代码、能读懂的图，把原资料讲不到的"为什么"补齐；让读者合上书能自己重做一遍。**

任何一条与之冲突的做法（省掉实验、编个数字、贴截图凑数、写"课件第 N 页说了"），都算失败。
