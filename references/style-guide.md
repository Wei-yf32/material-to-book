# 写作规范（style-guide）

## 读者画像

默认读者是**零基础但聪明**的工科本科生：会一点数学、没写过 Python、没跑过实验、分不清"库函数"和"自己写的函数"。所以：

- 任何库函数第一次出现，要写清"它吃进什么、吐出什么、参数是什么意思"；
- 任何符号第一次出现，要说它是标量/向量/矩阵、形状是什么；
- 任何结论，要给一个能算的数字。

如果用户是工程师/研究生，把"语言入门"部分压缩，把"边界条件、复杂度、失效模式"加重。

## 章骨架

```html
<h1>07　支持向量机：把分类线放在最宽处</h1>
<p class="h1note">一句话说明这一章解决什么问题、读完能做什么。</p>

<div class="box key"><strong>本章目标</strong><ul>…4~6 条可验收的能力…</ul></div>

<h2>导入：…</h2>            <!-- 用真实事件/真实数据开场，链接到本章问题 -->
<h2>7.1　直觉：…</h2>        <!-- 生活类比，不用公式 -->
<h2>7.2　形式化：…</h2>      <!-- 定义、公式、推导，每个符号解释 -->
<h2>7.3　例子：…</h2>        <!-- 手算一个完整小例，每步给中间值 -->
<h2>7.4　代码：…</h2>        <!-- INCLUDE-CODE + 逐段讲 -->
<h2>7.5　实验 7-A：…</h2>    <!-- box lab，八节骨架 -->
<h2>7.6　常见错误与陷阱</h2>
<h2>7.7　小结、动手改一改与延伸阅读</h2>
<h2>7.8　原资料回顾</h2>   <!-- box key：原资料小结逐条抄 + 本书额外补了什么 -->
<h2>7.8　本单元课件覆盖表</h2>
```

- 编号用 `章号.序号`，不要用裸数字（除非整章已是裸数字风格，此时**沿用**，不要重排全章）。
- 每章 15k~35k 汉字。低于 8k 基本是搬运。
- 每节开头先给一句"这一节要回答什么"，结尾给一句"所以结论是"。

## 深度四层（缺一层就是不合格）

1. **直觉**：生活类比，禁止公式。例：SVM 的间隔 = "在两类之间修一条最宽的路"。
2. **形式化**：定义 + 公式 + 推导，每个符号解释含义与形状。
3. **真实数值**：自己跑出来的数字、表格、图。例："C=0.01 时 97.2% 的样本都成了支持向量"。
4. **边界**：什么时候失效、代价是什么、和相邻方法怎么比。例："核 SVM 的复杂度是 O(n²)~O(n³)，n=10 万时不可用"。

## 语言

- 禁用词：首先、其次、再次、最后（作段落连接词时）、综上所述、值得注意的是、众所周知、不难发现、让我们、总而言之。
- 一段 ≤ 4 句；一句话 ≤ 40 字为宜。
- 少用"我们可以看到"，直接说"表 3-2 显示"。
- 术语首次出现给英文：`间隔（margin）`、`支持向量（support vector）`。
- 中文与英文/数字之间留一个空格；中文标点用全角。
- 不要用"笔者认为"；用事实和数字说话。

## 公式

- HTML 链：`\( ... \)` 行内、`\[ ... \]` 独立成行。**不要用 `$...$`**（MathJax 配置只认前两种）。
- 公式里的 `<`、`>` 必须写 `&lt;`、`&gt;`，否则浏览器当标签开头，会把后面半页吞掉（这是本项目最常见的灾难性 bug，用 `fix_lt.py` 兜底）。
- 独立公式后如果要编号，写成 `（式 3-7）` 并保证编号与章号一致（`numcheck.py` 会查）。
- 矩阵用 `\begin{pmatrix}`；中文说明放公式外，不要塞进 `\text{}` 里太长。

## 图

- 只能由脚本生成：`matplotlib` + `figstyle.py`（统一配色、中文字体、文字转 path）。
- 图注写三件事：**画的是什么、数据从哪来（文件+脚本）、和原始材料一致还是不同**。
- 数据图优先：散点、折线、条形、热力图、直方图。不要用"示意图"代替数据图；示意图只用于流程/结构。
- 每张图都要在正文里被引用一次（"图 3-6 显示……"），否则删掉。
- 一图多面板时用 `(a)(b)(c)`，标题写在面板上方。

## 表

- 一律 `<thead>` + `<tbody>`；数字列加 `class="num"`（右对齐）。
- 表头短的列容易挤成两行，用 `<th style="width:12%">` 固定比例。
- 表格只放"能对比的数字"，不要把整段文字塞进单元格。

## 代码块

- **只能 INCLUDE**，不许手写进 HTML（否则无法保证可运行）。
- 顶部有文件条（构建器自动加）：`src/vol4/ch12_id3.py`。
- 块前 1~2 句导语：这段代码要解决什么、看的时候注意哪一行。
- 块后按 5~15 行一组讲，每组一段（"前半段做三件事：……"）。
- 单块 ≤ 400 行（含注释）。超了拆成多个文件或只贴核心函数。

## 提示框

| class | 用途 |
|---|---|
| `box note` | 补充直觉、类比、背景 |
| `box warn` | 常见错误、坑、代价 |
| `box key` | 本章目标、结论、要点（也用做"回顾"块） |
| `box lab` | 实验（八节骨架，见 experiment-spec.md） |
| `box paper` | 论文/资料出处与"这篇到底做了什么" |

## 改版时的铁律

- **不复用旧 AI 文稿**：资料夹里若已有 AI 生成的汇总/讲解，只当反例看（它们通常把"逐行解释"写成"逐行翻译"），一行都不要搬。
- **只增不减**：删任何东西都要在交付说明里写清删了什么、为什么。

- **只增不减**：删任何一段都要在交付说明里写清楚"删了什么、为什么"。
- 不重排全章编号去"统一风格"——沿用该章既有风格，插队用 `x.y` 或 h3。
- 每次改完必须重跑 `preview.py --pdf`；跨章引用必须用 `numcheck.py`/`_chref.py` 复查。
