# 资料成书（material-to-book）

把一文件夹杂乱资料整理成一本**能读、能跑、能对照**的书。核心不是"总结"，而是**重建**：把散在几十个 PDF、若干脚本、notebook 里的知识，按学科逻辑重排成一份有先修关系、有实验、有真实数字、有图的讲义，并让原始资料里的每一页都在新书里有归属。

## 它先问你

装好之后，第一次接到任务它会先做一次访谈（十四问，可整段发给你勾选），因为下面四件事只有你知道：

- **哪些是主线**：教材、教辅、课件、旧讲义各自算什么角色（主线／扩展／参考／不用）。
- **按什么顺序排**：教材顺序、考点顺序、项目顺序，还是概念依赖顺序；允许混搭。
- **收到多深**：定义定理是否全含、例题是否进正文、证明是否要能证全、课后题是否逐题解。
- **要不要代码与工程案例**：数学课可以零代码，模电、数据结构这类课通常要 2–3 档，并要一节完整的工程/信号流程。

它会扫一遍资料夹，报出每个文件的页数、有没有文字层、是不是扫描件，给出角色判断与置信度，再让你确认。答案写进 `book.json` 的 `intake` 段，后面每一章都按这个口径写。

## 它怎么干活

1. **侦察**：给每个源文件建索引，测页码偏移（扫描版教材的 PDF 页 ≠ 书上页码），算出覆盖表。
2. **规划**：定卷、定章、定每章字数与图数，画先修关系图。
3. **规范先行**：先写排版规范与一章样板，定下定义／定理／证明／例题／注／习题的块样式与编号制度（"第 6 章""6.1"，不补零），再并行写其余章。
4. **写作**：一章一个写手，各自只改自己的文件；每章要有导入、形式化、例题、常见错误、习题（含教材原题逐题解）。
5. **构建**：HTML → 无头浏览器打印 → 两遍法回填目录页码、书签、页眉页脚 → 合订 PDF。
6. **质检**：结构体检、公式渲染、越界、空白页、数字可追、超集审计（逐页核对"这一页的内容在新书里有没有"）。
7. **交付**：合订 PDF、分卷 PDF、交付说明、交接文档；源料留在 `_build` 里可重建。

## 产物

默认多卷 PDF（封面、目录、书签、真图、跑过的代码）；也能出 DOCX、PPT、单文件 HTML、Markdown。

## 边界

- 扫描件没有文字层，只能逐页读图，速度取决于页数；
- 它不会替你决定"哪本教材是权威版本"，这要在访谈里说；
- 原文有错时它会算一遍再标出来（印误／表述／结论错三档），但不会静默改成自己的版本。

## 依赖

Python 3.12（pymupdf、matplotlib、numpy、pandas、pygments）+ Edge（打印）+ 中文字体。装好后可用包内 `scripts/doctor.py` 一键体检。
